Mind Canvas LLM Spec (JSON-only Snapshot Generator)

Purpose
- This spec is for an AI agent that generates presentation-like canvas scenes for Mind Canvas.
- The agent must output valid JSON only (no markdown, no prose, no code fences).
- The output should be directly loadable via "Load snapshots from JSON".

Output Contract
- Return exactly one JSON object with this shape:
  {
    "step": number,
    "snapShot": Snapshot[]
  }
- step: zero-based index of the active step.
- snapShot: array of steps. Each step is one scene.
- Do not return any extra keys outside this payload unless explicitly requested.

Top-level Types
- Snapshot:
  {
    "nodes": CanvasNode[],
    "edges": CanvasEdge[]
  }

- CanvasNode is one of:
  1) BoxNode ("type": "box")
  2) TextNode ("type": "text")

- CanvasEdge:
  {
    "id": string,
    "type": "edge",
    "sourceNodeId": string,
    "targetNodeId": string,
    "sourceAnchor": "auto" | "top" | "right" | "bottom" | "left",
    "targetAnchor": "auto" | "top" | "right" | "bottom" | "left",
    "color": string,
    "width": number,
    "dashed": boolean,
    "arrowStart": boolean,
    "arrowEnd": boolean,
    "route": "curve" | "straight" | "elbow",
    "curve": number,
    "opacity": number,
    "zIndex": number,
    "transition": "spring" | "none",
    "entranceAnimation": "none" | "fade" | "draw",
    "replayEntranceOnStepChange": boolean
  }

Code-based Generation Rules
- IDs must be unique within each step for nodes and edges.
- Every edge sourceNodeId/targetNodeId must reference existing node IDs in the same step.
- Include both "nodes" and "edges" arrays for every step, even if empty.
- Do not output legacy node type "rect". Use "box".
- Use only enum values defined in this spec.
- Keep numeric fields numeric (no quoted numbers).
- Keep booleans boolean (no quoted booleans).
- Preferred color format: hex (e.g. "#ffffff").
- Recommended default transition: "spring".

Runtime Coordinate Notes (from current app behavior)
- The canvas origin is centered in the viewport at startup.
- Treat (0, 0) as the visual center point.
- Positive x moves right, negative x moves left.
- Positive y moves down, negative y moves up.

Edge Geometry Notes (from current renderer)
- If sourceAnchor/targetAnchor is "auto", anchor side is chosen by center-to-center direction:
  - horizontal dominance => left/right
  - vertical dominance => top/bottom
- Text node bounds are estimated (not exact glyph bounds):
  - width ~= max(120, fontSize * 2.5 + paddingX * 2) * scale
  - height ~= max((fontSize * lineHeight + paddingY * 2) * scale, 32)
- For cleaner lines, prefer explicit anchors on structured layouts:
  - horizontal chains: sourceAnchor="right", targetAnchor="left", route="straight"
  - vertical chains: sourceAnchor="bottom", targetAnchor="top", route="straight"
  - mixed directions: route="elbow" can reduce visual overlap
- Recommended minimum spacing to reduce edge crowding:
  - horizontal node-gap: 260+
  - vertical node-gap: 170+

Layout Hygiene Rules
- Default to fewer nodes over decorative density.
- Avoid unnecessary full-canvas background box nodes unless explicitly requested.
- Prefer text nodes for labels/chips/titles when a box shape is not required.
- Keep scenes center-aligned around (0,0) unless prompt requests asymmetry.
- If a step uses many edges, increase node spacing before adding more curves.

Component Mode Notes
- If contentKind is "component", set:
  - componentId to a valid ID (currently "badge-note" or "metric-chip")
  - componentProps to an object
- If not using component mode, still include componentId and componentProps with safe defaults.

Minimal Safe Defaults
- Use these if a prompt does not specify style values:
  - opacity: 1
  - scale: 1
  - rotate: 0
  - zIndex: 0
  - radius: 0
  - borderWidth: 0
  - borderColor: "#ffffff"
  - borderEnabled: true
  - transition: "spring"
  - replayEntranceOnStepChange: false
  - box entranceAnimation: "pop"
  - text entranceAnimation: "pop"
  - edge entranceAnimation: "draw"

Agent Prompting Template
- System behavior for the JSON generator:
  - Convert user topic/instructions into a multi-step visual narrative.
  - Output valid JSON payload only.
  - No markdown fences, no natural language explanation.
  - Ensure schema correctness and enum correctness.
  - Ensure all edges reference existing nodes.
  - Keep layouts centered and readable around origin.
  - Prefer explicit anchors when a linear flow is intended.

- User prompt example:
  - "Create a 4-step snapshot JSON explaining how photosynthesis works. Step 1: context, Step 2: light reaction, Step 3: Calvin cycle, Step 4: summary. Use mostly text nodes and a few connecting edges."
